## 三、运行前提

- 目标应用停在：**<页面名>**（<截图位置说明>）

## 四、怎么知道它在干什么

状态栏第一行固定显示：`无障碍：已连接 / 未连接`

| 第二行显示 | 含义 |
|---|---|
| `(3/20) 搜索：歌名` | 正在处理第 3 项 |
| `(3/20) 等结果：歌名` | 已点提交，等列表刷新 |
| `下载：标题｜副标题` | 正在点某一行的按钮 |
| `已手动停止` | 你按了停止 |
| `连续两处零产出，停在第 N 项` | 熔断，打开看 App 有没有弹限制提示 |
| `填不进歌名` / `界面没恢复` | 输入框或页面状态异常 |

## 五、性能提醒（重要）

- 这类脚本是持续消耗型：**单次连续不超过 20–30 项**，中间停 1–2 分钟
- 低配机（4G 运存以下）单次不超过 10–15 项
- **不要夜间挂机**：服务与目标应用可能被系统回收，回收后不会自己恢复
- 不要边充电边长时间跑（发热会触发降频，越跑越卡）
- 出现这些就停：每项耗时明显变长、滑动不跟手、点击要等两三秒才有反应、手机发烫

## 六、出问题怎么报

发这三样，定位会快很多：

1. 状态栏第二行的原文
2. 第几项出的问题、目标应用当时的截图
3. 手机型号 + 系统版本（判断保活/受限设置问题）

## 七、边界

- 仅限个人学习与效率用途；自动化操作可能违反平台用户协议，账号风险自担
- 不提供绕过付费墙、验证码、鉴权的手段
- 目标应用改版会导致失效，届时需要用新版安装包重新取一遍控件 id
